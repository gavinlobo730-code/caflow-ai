- **POST-A-349** · `inventory-fixed-assets` · low · days — **A month of depreciation that is posted while the same month is being reversed can end with the register saying posted and the ledger saying reversed.** `reverse_depreciation` writes the register first (so a reclassification that lands in between is detected) and reverses the journal second, and a second request that posts the SAME month of the SAME asset in that window finds the journal still live, is handed it by the kernel's duplicate check without a new entry, writes the register up again, and is then reversed by the first request. THE CHEAP FIXES WERE LOOKED AT AND DO NOT WORK (28-10-2026, reading the two routes): a half-done REVERSAL (register claimed, journal not yet reversed) and a half-done POST (journal written, register not yet moved) leave the identical state (register behind, journal live) and the retry that adopts a live journal is deliberate for the second, so the post cannot refuse it on state alone, and a compare-and-set on the posted-through date does not help because the second request reads the register AFTER the first one's claim.
