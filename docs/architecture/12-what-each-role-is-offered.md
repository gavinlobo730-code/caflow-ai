# What each role is offered

Generated by `apps/api/scripts/role_by_screen.py`; do not edit by hand. `apps/api/tests/test_the_role_by_screen_table_is_current.py` fails when this file and the code disagree.

**What it reads.** The role templates in `apps/api/core/permissions.py` (what `rbac()` falls back to when a person has no grant of their own), the one table of which permission opens which area of the firm menu and which screen (`apps/web/lib/access/screenAccess.ts`: since 21-11-2026 the menu, the page and the guide all follow it, and no list of roles hides an area or an address), each firm panel's entries and the permission each names itself, the Settings links (`apps/web/lib/settings/groups.ts`, each asked of the same table) and the client workspace's sections (`apps/web/lib/workspace/ClientNavContext.tsx`).

**What it does not read.** A per-person grant or block (the Team screen's grid) changes what one person is offered and is not here: this is what each ROLE starts with. A page drawn for a role may still narrow its rows to the clients the person is assigned to (a Partner sees every client; every other role sees only assigned ones), hide a button the person may not use, or be refused by the server. A Client-portal contact and an employee are not staff and have their own portals, which read only their own client's or their own records (see `docs/design-record/tenancy-and-security.md`).

`yes` means the role is offered it; `-` that it is not.
